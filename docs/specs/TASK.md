Задание: «Ипотека без сюрпризов»

## Легенда 

Вы — бэкенд-команда финтех-стартапа. Люди берут ипотеку на 25 лет и не понимают, сколько реально переплатят и что будет, если ставка вырастет. Ваш сервис должен показывать это честно и быстро.

## Стек 

Java 25, Spring Boot 4, Spring Security, PostgreSQL, MongoDB, Redis, RabbitMQ, Docker Compose. Фронт — любой простой (Thymeleaf/HTMX или минимальный React).

## Что должно работать

- Калькулятор (доступен без логина) Вход: стоимость жилья, первый взнос, срок, ставка, тип платежа (аннуитетный или дифференцированный). Выход: ежемесячный платёж, переплата, полный график платежей. Досрочные погашения: разовые и регулярные, с выбором «уменьшить срок» или «уменьшить платёж».
- Регистрация и логин (Spring Security) Email + пароль с подтверждением почты. OAuth2 через Google или GitHub. JWT: access + refresh, refresh-токены хранятся в Redis, logout их отзывает. Роли: USER и ADMIN.
- Личный кабинет Сохранять сценарии расчёта и сравнивать 2–3 сценария бок о бок.
- Админка CRUD банковских предложений (банк, ставка, минимальный взнос, максимальный срок). При изменении ставки улетает событие в RabbitMQ.

## Где что живёт

- PostgreSQL: Пользователи, роли, банковские предложения, сохранённые сценарии
- MongoDB: Рассчитанные графики платежей (документ на расчёт), история расчётов
- Redis: Кэш предложений и результатов расчёта по хэшу параметров, refresh-токены, rate limit на калькулятор
- RabbitMQ: Событие «ставка изменилась» → пересчёт затронутых сценариев → уведомление пользователю; письмо подтверждения почты

## Обязательные требования

- Деньги только в BigDecimal, округление явно задано.
- Расчётное ядро покрыто юнит-тестами, эталон — любой банковский калькулятор.
- Интеграционные тесты на Testcontainers: минимум auth-флоу и один сценарий с очередью.
- Миграции через Flyway или Liquibase.
- Всё поднимается одной командой docker compose up.
- README: как запустить, схема архитектуры, принятые решения и почему.

## Со звёздочкой

- Экспорт графика в PDF асинхронно через очередь.
- Dead letter queue и ретраи для упавших сообщений.
- Вход по одноразовому коду на почту (magic link / OTP).
- Плавающая ставка: график «что будет, если ставка вырастет на N %».
- Метрики и трейсинг (Actuator + Prometheus/Grafana).

## Сдача

Репозиторий + 5-минутное демо: регистрация → расчёт → сохранение → админ меняет ставку → пользователю приходит уведомление с пересчётом.
